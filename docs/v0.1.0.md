## BREAKING

### G1: glance-check fails closed when zero files are scanned

[#32](https://github.com/Alarm2024/glance/pull/32), commit [`78d0ccc`](https://github.com/Alarm2024/glance/commit/78d0cccaff92855f48d634ab25b1955894657d7b).

`glance-check` used to exit 0 when it had nothing to scan. An empty `paths` input, with neither `demo/fixture.json` nor `status.json` present, printed a notice and the job stayed green.

That case now exits 1:

```
glance: no files to scan - set `paths` (zero files scanned; failing closed)
```

A `paths` value that is empty or blank is the same input: it may scan two default files, `demo/fixture.json` and `status.json`, each one when it exists. If neither file exists, it fails closed. If one of them exists, that file is scanned and this break does not fire.

Workflows that depended on the old silent pass need `paths` set to the status files the pipeline writes. See [glance-check in the README](../README.md#glance-check-github-action).

Listing a path that is not a file is a different failure (`requested path does not exist`, [#27](https://github.com/Alarm2024/glance/pull/27), [`3ae4dcd`](https://github.com/Alarm2024/glance/commit/3ae4dcd4a7f8be455f2e1c60f5b0d558dc8728f4)). G1 is the zero-file case and nothing else.

## Scan scope

glance-check scans the files it is given and no others. With `paths` set, files outside that list are not checked. A green result does not mean the rest of the repository is clean.
